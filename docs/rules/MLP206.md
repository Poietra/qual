# MLP206: Literal play duration shorter than one frame

`manim-lint` reports `MLP206` when a `Scene.play` / `Scene.wait` call has a
literal positive duration that is provably shorter than one frame period at
every analyzed profile's frame rate.

The frame grid is `np.arange(0, run_time, 1/frame_rate)`: a run time below
one frame period still renders exactly one frame, so the animation shows
only its final state while the whole per-play startup (argument compile,
hash, begin copies, cleanup, partial stream) is paid for a single frame of
output.

- Default severity: `warning`
- Minimum confidence: `certain`
- Implementation phase: `3`
- Fix: none

Zero and negative literal durations are a runtime `ValueError` and belong
to `MLC104`, not this rule. A duration that is not a literal at the call
site (a variable, a computed value) stays silent — the clamp is only
reported when it is provable.

## Wrong

```python
class Demo(Scene):
    def construct(self):
        square = Square()
        self.play(FadeIn(square), run_time=0.004)  # < 1/60 s at 60 fps
```

## Right

```python
class Demo(Scene):
    def construct(self):
        square = Square()
        self.play(FadeIn(square), run_time=0.5)
```
