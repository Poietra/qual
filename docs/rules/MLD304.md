# MLD304: Renderer-divergent effect reached without a guard in a multi-renderer run

`manim-lint` reports `MLD304` only when the run actually targets more
than one renderer (`--profile all` with both a Cairo and an OpenGL
profile) and the lifecycle interpreter proves that a renderer-divergent
membership effect is reached on **every** path.

- Default severity: `warning`
- Minimum confidence: `medium`
- Implementation phase: `4`
- Fix: none

The implemented divergence is the fixed-object unfix of DESIGN 3.5:
`ThreeDScene.remove_fixed_in_frame_mobjects` /
`remove_fixed_orientation_mobjects` only unregister the camera fix under
Cairo, but the OpenGL branch additionally removes the object from the
Scene. Rendering the same scene with both renderers therefore produces
different membership — the object stays visible under Cairo and vanishes
under OpenGL.

Silent by design:

- single-renderer runs — a project that explicitly targets one renderer
  is never asked for renderer guards (DESIGN 7.4 prose);
- any call behind a branch: the event certainty joins to `Maybe`, so a
  renderer guard (or any other condition) silences the rule.

Wrong (with `--profile all` over cairo + opengl profiles):

```python
self.add_fixed_in_frame_mobjects(label)
self.remove_fixed_in_frame_mobjects(label)   # visible on cairo, gone on opengl
self.wait()
```

Right:

```python
self.add_fixed_in_frame_mobjects(label)
self.remove_fixed_in_frame_mobjects(label)
self.remove(label)                           # pin the membership explicitly
```
